Insight Engine — How Every Decision Is Made
This page is the "show your work" section. Every recommendation on this platform is based on a chain of evidence — not a single number, and never a black box. The engine requires at least two independent signals to cross their danger thresholds before it escalates to a recommendation. This prevents false alarms and ensures every action is defensible to regulators, auditors, and investors.
Two-signal rule: A single bad metric triggers a "watch" status. Only when two or more metrics simultaneously breach their thresholds does the system escalate to "recommended action." This mimics how experienced portfolio managers think — one warning can be noise, two warnings are a pattern.
HTGC had 4 simultaneous signals: Health below floor, IRR below hurdle, IFRS 9 Stage 3 credit flag, and DSCR below minimum. Four concurrent red flags is the clearest exit signal the system can produce.
Liquidity produced zero signals: Not a single liquidity metric is in danger zone. The green status is earned — the system didn't default to green; it verified every metric and found nothing to flag.
How it works: No alert fires on a single metric alone. The engine waits until at least two criteria cross their thresholds simultaneously before escalating — reducing false alarms and ensuring every recommended action has multi-dimensional support.

FRAGILE vs ROBUST framework: Every holding is classified as Fragile (exit candidate), Watch (monitor), or Robust (eligible for reinvestment). This classification drives all portfolio actions automatically and consistently.

Settings — The Investment Policy Statement in Digital Form
The sliders and thresholds on this page are the digital version of your Investment Policy Statement (IPS) — the formal document that defines what this portfolio is allowed to do. When a threshold is breached, the system automatically flags it. Changing a threshold here changes what the system considers acceptable.
Drift Trigger ±5%: If any holding drifts more than 5 percentage points from its target, the system automatically flags it for rebalancing. This prevents "drift creep" where a portfolio silently becomes something very different from what was approved.
Single-Name Limit 5%: No single company or fund can exceed 5% of the portfolio without board approval. KKR is currently at an approved exception of 19%. Any new addition triggers an immediate alert.
Hurdle Rate 10%: Any holding earning below 10%/yr is automatically classified as underperforming and flagged for review. HTGC (6.1%) and ICLN (3.2%) both fail this test — hence their exit recommendations.

🔬 Advice Backtest
A controlled experiment: does following Eterna's recommendations actually improve results — tested against thousands of unknown future markets, with no hindsight?
🎯 What this test does — and honestly, what it doesn't
For each portfolio, we take the exact recommendations Eterna's own engine produces (exit fragile holdings, trim drift, add underweight quality), build an "advised" version, then run both the original and the advised portfolio forward through thousands of randomized future market paths. The same random shocks hit both versions, so it's a fair fight. Neither portfolio knows which future it will face — that's the "no hindsight" part.

This tests whether Eterna's logic is sound — whether applying its rules improves the risk/return profile against an unknown future. It does not claim "Eterna would have earned you X% last year" — that would need real historical price data, which a live platform pulls from the market, not from these snapshots.
Method: Monte Carlo forward simulation Paths: 5,000 per portfolio Horizon: 1 year Fairness: identical shocks, both versions Measures: Sharpe & Sortino

🏗️ How It's Built
The engineering behind the platform — how the AI analyst turns a live portfolio into plain-English answers, and what happens when the network isn't there.
🧩 Architecture at a glance
This is a single-file HTML application — no build step, no backend server, no database. Every metric, chart, and recommendation is computed in the browser from the portfolio data. The one external call is to the Claude language-model API, which turns computed numbers into narration. Crucially, that call is optional: if it's unavailable for any reason, a local analysis engine takes over so the platform never breaks.
Frontend: Vanilla JS + Chart.js State: in-memory, no DB AI: Claude API (optional) Resilience: local fallback engine Deploy: one .html file
The AI Pipeline
How a question becomes an answer — four stages, with a safety net
Stage 1 · Context assembly
📊 Build live portfolio context
The platform reads the active portfolio and computes fresh metrics — IRR, Sharpe, VaR, beta, health scores, fragile holdings — with computeMetrics(). These real numbers are packed into a system prompt so the model reasons about this book, not generic advice.
↓
Stage 2 · The call
🤖 Send to Claude
A fetch() POSTs the system prompt + conversation to api.anthropic.com/v1/messages (model claude-sonnet-4-6). A role-specific system prompt (CEO / CFO / PM) shapes the voice.
↓
Stage 3 · Parse
🔍 Extract & render
The response JSON is parsed — data.content[0].text — then run through a lightweight markdown renderer into styled chat bubbles. On a non-OK status, it throws to Stage 4.
↓  on any failure  ↓
Stage 4 · The fallback (the important part)
🛡️ Local analysis engine takes over
If the network is down, the app is opened as a local file (CORS), or the API is unreachable, localAnalysisEngine() generates a genuine, portfolio-specific answer entirely in the browser — detecting intent (risk, exits, rebalancing, fees…) and reading the same live metrics. The app flips _aiLiveMode = false and routes straight here next time. The user still gets a real answer — never an error.
Why the fallback matters: most demos die the moment they're opened offline or outside their host environment — the AI call fails and the feature is dead. Here, the language model is an enhancement, not a dependency. The platform degrades gracefully to a deterministic local engine, so a reviewer opening the file on a plane still sees the AI analyst work.
